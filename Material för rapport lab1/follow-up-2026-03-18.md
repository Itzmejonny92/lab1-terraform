# Uppfoljning Lab 1 Terraform

Datum: 2026-03-18

Sedan min tidigare inlamning har jag gjort en uppfoljning for att verifiera att deploymenten fungerar aven i GitHub Actions och inte bara lokalt. Bakgrunden var att `terraform plan` fungerade i CI, medan `terraform apply` tidigare bara gick igenom lokalt med fungerande GCP-credentials.

Idag testade jag den uppdaterade service account-nyckeln som har utokade GCP-behorigheter. Jag verifierade forst lokalt att bade `terraform plan` och `terraform apply` fungerade med `GOOGLE_APPLICATION_CREDENTIALS` satt till den nya JSON-filen. Darefter uppdaterade jag GitHub Actions-workflown sa att den kan kora en manuell `apply` via `workflow_dispatch`.

Eftersom projektet fortfarande saknar delad remote state i CI valde jag inte att kora en vanlig `apply` direkt. I stallet importerar workflowen de resurser som redan finns i GCP till jobbets temporara state innan `terraform apply -auto-approve` kors. Pa sa satt undviks att GitHub Actions forsoker skapa dubbletter av redan existerande resurser.

Efter den andringen korde jag workflown manuellt i GitHub Actions och fick en helt gron korning. `lint`, `security`, `validate`, `plan` och `apply` gick igenom, och jag har lagt till en screenshot som bevis i rapportmaterialet.

Min uppfoljande slutsats ar darfor att uppgiften nu ar verifierad bade lokalt och i GitHub Actions. Den tidigare blockern kring `apply` ar lost med den nya nyckeln och den justerade workflowen.
