# Uppföljning Lab 1 Terraform

Datum: 2026-03-18

Sedan min tidigare inlämning har jag gjort en uppföljning för att verifiera att deploymenten fungerar även i GitHub Actions och inte bara lokalt. Bakgrunden var att `terraform plan` fungerade i CI, medan `terraform apply` tidigare bara gick igenom lokalt med fungerande GCP-credentials.

Idag testade jag den uppdaterade service account-nyckeln som har utökade GCP-behörigheter. Jag verifierade först lokalt att både `terraform plan` och `terraform apply` fungerade med `GOOGLE_APPLICATION_CREDENTIALS` satt till den nya JSON-filen. Därefter uppdaterade jag GitHub Actions-workflown så att den kan köra en manuell `apply` via `workflow_dispatch`.

Eftersom projektet fortfarande saknar delad remote state i CI valde jag inte att köra en vanlig `apply` direkt. I stället importerar workflowen de resurser som redan finns i GCP till jobbets temporära state innan `terraform apply -auto-approve` körs. På så sätt undviks att GitHub Actions försöker skapa dubbletter av redan existerande resurser.

Efter den ändringen körde jag workflown manuellt i GitHub Actions och fick en helt grön körning. `lint`, `security`, `validate`, `plan` och `apply` gick igenom, och jag har lagt till en screenshot som bevis i rapportmaterialet.

Min uppföljande slutsats är därför att uppgiften nu är verifierad både lokalt och i GitHub Actions. Den tidigare blockern kring `apply` är löst med den nya nyckeln och den justerade workflowen.
